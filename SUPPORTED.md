# Supported AsciiDoc and DITA content

The converter produces individual DITA 1.3 **concept**, **task**, and
**reference** topics. Successful output is validated against the vendored DITA
1.3 plus Errata 02 schemas. It does not claim that every possible AsciiDoc
extension has a lossless DITA equivalent.

## Supplied-file audit

The converter was tested against the source patterns and XML vocabulary in the
six supplied plugin files. The source counterparts currently available in the
local documentation clone all convert successfully in standalone mode.

| Supplied file | Role | Audited vocabulary | Result |
| --- | --- | --- | --- |
| `con-preinstalled-dynamic-plugins.dita` | Concept topic | `concept`, `title`, `shortdesc`, `conbody`, paragraphs, unordered lists, inline code, YAML code blocks, notes | Covered |
| `ref-ga-plugins.dita` | Reference topic | `reference`, `refbody`, `section`, four-column CALS table, header/body rows, bold, inline code, external cross references | Covered |
| `ref-technology-preview-plugins.dita` | Reference topic | Same table vocabulary plus an important note and an included snippet | Covered |
| `ref-deprecated-plugins.dita` | Reference topic | Title, short description, reference body, section | Covered |
| `rhdh-plugin-test-conversion.ditamap` | DITA map | Topic ordering through `topicref` | Readable as a reference; not generated by single-topic conversion |
| `dynamic-plugins-reference-pdf.ditamap` | DITA bookmap | Book metadata, front matter, chapter map, back matter and generated lists | Readable as a reference; not generated by single-topic conversion |

The supplied files are snapshots from a different content revision than the
current source clone, so row and plugin counts differ. The element sets match
for the three nonempty topic sources. The supplied deprecated-topic snapshot
contains an empty `<section>` that is absent from the current source; the
converter does not invent an empty section.

Two problems in the supplied output should not become expected behavior:

- The first table header contains escaped text `&lt;b&gt;Name&lt;/b&gt;`, while the
  other three headers contain real `<b>` elements. The converter emits a real
  `<b>Name</b>` element.
- The supplied concept and rendered PDF retain the unresolved text
  `{product-short}` in one paragraph. The converter reports unresolved
  attributes and does not label such output successful.

## Supported source constructs

The pinned Asciidoctor parser and `asciidoctor-dita-topic` backend handle the
following constructs, subject to DITA schema rules:

- document title and `[role="_abstract"]` short description
- paragraphs, sections, examples, quotes, and preambles
- ordered, unordered, callout, and description lists
- CALS tables with headers, column widths, spans, and AsciiDoc cell content
- source/listing/literal blocks with language metadata and preserved whitespace
- notes, tips, important notices, cautions, and warnings
- images, external links, local cross references, and cross-document references
- bold, italic, monospace, keyboard, menu, button, footnote, and index-term inline content
- semantic monospace roles such as command, filename, option, and variable
- local attributes, attribute files, conditionals, tagged includes, and line-filtered includes

For a pasted topic, a missing `_{context}` or `-{context}` suffix is removed
only from explicit IDs and cross-reference targets. This produces a stable base
topic ID. A `context=value` override preserves the contextual suffix. A
`{context}` reference in prose is not removed and remains a missing-attribute
error.

If the attributes file belongs to a local Git clone and the pasted content
matches exactly one source topic, that path is used only to resolve local
includes. No guide or project is selected. Includes stay confined to the clone.

## Deliberate limits

- DITA maps and bookmaps organize topic files; they are separate artifacts from
  concept, task, and reference topics. Map generation is not part of the current
  single-topic or release-diff workflow.
- Nested sections, table footers, STEM, page/thematic breaks, titled
  admonitions, and other constructs without a direct DITA equivalent can
  produce errors or review diagnostics.
- Extensions that add custom AsciiDoc macros need an explicit converter mapping.
- Schema validation proves structural validity. It does not prove factual
  accuracy, URL availability, image availability, or publishing layout.

The upstream converter documents its mappings and known warnings at
<https://github.com/jhradilek/asciidoctor-dita-topic>. The DITA topic-type and
bookmap distinctions come from the OASIS DITA 1.3 technical-content
specification at
<https://docs.oasis-open.org/dita/dita/v1.3/os/part3-all-inclusive/langRef/containers/technical-content-elements.html>.
